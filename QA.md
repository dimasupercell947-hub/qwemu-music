## 2. Подтверждённые функциональные дефекты

### BUG-01 — удалённые плейлисты могут воскресать

**Приоритет:** P1  
**Файл:** `public/assets/main.js`  
**Места:** `loadCloud()`, `mergePlaylists()`

Сейчас клиент объединяет локальные плейлисты с серверными. Если плейлист удалён на одном устройстве, старый локальный список на другом устройстве может вернуть его при следующей загрузке. Аналогично избранное объединяется через объединение массивов, поэтому удалённые избранные треки могут появляться снова.

**Ожидаемое исправление:**
- определить источник истины и правила разрешения конфликтов;
- хранить версии/время изменения или tombstone-записи для удалений;
- не восстанавливать удалённые сущности простым объединением массивов.

**Критерий приёмки:** удаление плейлиста или избранного на устройстве A отражается на устройстве B после синхронизации; сущность не появляется снова после перезагрузки и повторного входа.

### BUG-02 — идентификатор трека нестабилен между устройствами

**Приоритет:** P1  
**Файл:** `public/assets/file-fingerprint.js`

Fingerprint включает имя файла, размер, `lastModified` и выборочные блоки содержимого. При копировании одной и той же композиции на другое устройство имя или время изменения могут отличаться — ID станет другим.

**Последствие:** синхронизированный плейлист содержит ID, которого нет у локальной копии трека.

**Ожидаемое исправление:**
- не включать изменяемые файловые метаданные в идентификатор содержимого;
- определить устойчивую стратегию идентификации аудио между устройствами;
- отдельно учитывать вероятность совпадения у выборочного хэша.

**Критерий приёмки:** одинаковый аудиофайл с разными именами и датами изменения получает один стабильный content ID; разные аудиоданные не должны ошибочно считаться одним треком.

## 3. Риски и дефекты, требующие отдельного подтверждения

### RISK-01 — CPU time при регистрации и входе

**Приоритет:** P1 до production  
**Файл:** `functions/api/[[path]].js`

PBKDF2 выполняется с 310 000 итераций. Это не доказанная ошибка, но стоимость вычислений нужно измерить на реальном Workers runtime и тарифе.

**Проверка:** измерить CPU time регистрации и входа, проверить лимиты тарифа и поведение при нескольких одновременных запросах. Не снижать стойкость паролей без отдельного security review.

### RISK-02 — health endpoint не проверяет доступность D1

**Приоритет:** P2  
**Файл:** `functions/api/[[path]].js`

`/api/health` возвращает `databaseConfigured: Boolean(env.DB)`. Наличие binding не доказывает, что запрос к базе реально проходит.

**Ожидаемое исправление:** выполнить безопасный короткий запрос к D1 и возвращать корректный статус зависимости без раскрытия внутренних ошибок.

**Критерий приёмки:** при недоступной/нерабочей D1 health-check не сообщает, что база полностью исправна.

### RISK-03 — ошибки вставки пользователя маскируются под конфликт аккаунта

**Приоритет:** P2  
**Файл:** `functions/api/[[path]].js`, регистрация

Любая ошибка INSERT сейчас превращается в HTTP 409 с сообщением, что логин или почта заняты. Временный сбой D1 также будет показан пользователю как конфликт.

**Ожидаемое исправление:** отличать нарушение уникальности от ошибок инфраструктуры; неизвестные ошибки передавать в общий безопасный обработчик 500.

**Критерий приёмки:** дубликат получает 409, сбой базы не маскируется под занятый логин.

### RISK-04 — пользователь может быть создан без выданной сессии

**Приоритет:** P2  
**Файл:** `functions/api/[[path]].js`, регистрация

Запись пользователя и создание сессии выполняются отдельными операциями. Если создание сессии завершится ошибкой после успешной вставки пользователя, регистрация завершится ошибкой, хотя аккаунт уже существует.

**Ожидаемое исправление:** согласовать создание аккаунта и сессии с помощью атомарного D1 batch/транзакционного сценария, если он совместим с используемым API.

**Критерий приёмки:** сбой на этапе создания сессии не оставляет частично созданный аккаунт без понятного восстановления.

### RISK-05 — истёкшие сессии остаются в D1

**Приоритет:** P2  
**Файл:** `functions/api/[[path]].js`

Сессии проверяются по `expires_at`, но в просмотренной логике не обнаружена периодическая очистка истёкших записей.

**Ожидаемое исправление:** добавить безопасную очистку старых сессий с ограниченным объёмом работы на запрос или плановую задачу.

**Критерий приёмки:** истёкшая сессия не авторизует пользователя и со временем удаляется из D1.

## 5. Что добавить в тестовую инфраструктуру

Приоритетный порядок:

1. **Интеграционные тесты Worker + D1.** Использовать официальный Cloudflare Workers Vitest integration / Workers Pool. Проверять реальные HTTP-запросы к Worker и локальную D1, а не наличие строк в исходниках.
2. **Регрессионные тесты синхронизации.** Два независимых клиента с разными локальными данными; проверка удаления, переименования, конфликтов и повторного входа.
3. **Тесты безопасности API.** Origin, CSRF, cookies, rate limit, лимит тела, изоляция аккаунтов.
4. **Браузерные E2E-тесты.** Проверить реальные кнопки, формы, навигацию, импорт файлов и Audio API. Playwright добавлять только если интеграционные тесты не закрывают UI.
5. **Wrangler dry-run.** В CI проверять не только сборку Pages Functions, но и конфигурацию Workers Static Assets с командой dry-run, совместимой с выбранной версией Wrangler.
6. **Проверка миграций.** На чистой локальной D1 применить все миграции и выполнить базовые INSERT/SELECT/UPDATE/DELETE.
7. **Проверка production readiness.** Настоящий D1 ID, существующая база, применённые миграции и настроенный secret; никаких фиктивных значений в production.

## 6. Что добавить в продукт

### P1 — необходимо для надёжной Web Edition

- Надёжная синхронизация с поддержкой удаления и разрешения конфликтов.
- Стабильные идентификаторы треков между устройствами.
- Понятный статус синхронизации: синхронизировано / ожидает / ошибка / офлайн.
- Кнопка повторной отправки несинхронизированных изменений.
- Экспорт и импорт метаданных аккаунта в JSON.

### P2 — улучшения

- IndexedDB для сохранения локальной библиотеки между перезапусками (с явным согласием пользователя и понятным управлением хранилищем).
- Восстановление плейлистов из резервной копии.
- Очистка старых сессий и rate-limit записей.
- Отдельный экран состояния облачного подключения.
- Доступность: focus states, клавиатурная навигация, reduced motion.
