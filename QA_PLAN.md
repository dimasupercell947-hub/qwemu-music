# QWEMU MUSIC Web Edition — QA-план

Версия проекта: 1.4.0  
Цель: проверить Web Edition после миграции на Cloudflare Workers + Static Assets + D1, выявить регрессии и определить следующий объём работ.

> Важно: этот документ составлен по статическому анализу исходников ветки `fix/cloudflare-workers`. Браузерные, D1-интеграционные и production-тесты ещё не выполнены. Статус «проверить» не означает, что дефект уже воспроизведён.

## 1. Текущая картина

| Область | Что есть в коде | Статус |
|---|---|---|
| Интерфейс | Главная, медиатека, избранное, плейлисты, настройки, профиль | Есть; нужен браузерный прогон |
| Аудио | HTML Audio, локальные файлы, очередь, seek, громкость, repeat | Есть; нужны проверки форматов и браузеров |
| Хранение | localStorage, fingerprint файлов | Есть; проверять квоты и восстановление |
| Аккаунты | Регистрация, вход, выход, профиль | Есть; нужен интеграционный тест с D1 |
| Сессии | Cookie, срок 14 дней, хэш токена | Реализовано; проверить реальные заголовки и истечение |
| CSRF | Same-origin + CSRF cookie/header | Реализовано; проверить негативные сценарии |
| Rate limit | D1-счётчик по IP и типу операции | Реализовано; нагрузка и обход не проверены |
| Синхронизация | Плейлисты, избранное, настройки | Реализована базовая версия; есть риски конфликтов |
| Cloudflare | Worker, Static Assets, D1, migrations | Конфигурация подготовлена; сборка/deploy не подтверждены |
| Автотесты | Smoke-проверки структуры и исходников | Не проверяют реальные HTTP/D1 сценарии |

## 2. Найденные риски и возможные баги

Приоритеты: **P0** — блокирует релиз или создаёт критический риск; **P1** — важная функция может работать неверно; **P2** — качество, UX или расширение.

| ID | Приоритет | Наблюдение | Что сделать |
|---|---|---|---|
| Q-01 | P1 | Слияние избранного использует объединение локального и облачного списков. Удалённые на другом устройстве элементы могут вернуться из устаревшего локального состояния | Ввести версионирование/updatedAt и понятную стратегию разрешения конфликтов; добавить тест двух устройств |
| Q-02 | P1 | Слияние плейлистов объединяет локальные и облачные записи по ID. Удаление на одном устройстве не имеет tombstone-маркера; устаревшая копия может восстановить запись при следующей записи | Добавить tombstones или версионированный snapshot; тест удаления offline/online на двух клиентах |
| Q-03 | P1 | Smoke-тест проверяет наличие строк в исходниках, но не выполняет реальные запросы к Worker и D1 | Добавить Worker integration tests с локальной D1 и проверками ответов/схемы |
| Q-04 | P1 | Сборка использует `wrangler pages functions build`, а затем ожидает `dist/worker/index.js`. Это должно быть подтверждено фактическим выводом Wrangler 4 | Запустить сборку на чистой машине и сверить реальный output path; при необходимости перейти на поддерживаемую сборку Worker |
| Q-05 | P1 | В `/api/health` возвращается HTTP 200 и `ok: true`, даже если D1 не подключена; отдельное поле сообщает `databaseConfigured: false` | Разделить liveness и readiness: readiness должна возвращать неуспешный статус при недоступной обязательной D1 |
| Q-06 | P1 | PBKDF2 использует 310 000 итераций. Фактическое CPU time Workers на выбранном тарифе не измерено | Замерить регистрацию и вход на локальном и deployed Worker; проверить лимиты и p95 |
| Q-07 | P2 | Библиотека и сами File/Blob URL существуют только в текущей вкладке. После перезагрузки файлы нужно выбирать заново | Решить продуктово: оставить осознанный временный импорт или добавить IndexedDB/OPFS с квотами и очисткой |
| Q-08 | P2 | Плейлист хранит ID файлов, но не аудиофайлы; после повторного импорта ID зависит от имени, размера, lastModified и выборок содержимого | Проверить восстановление плейлиста после перезапуска и на другом устройстве; предусмотреть «не найден файл» и повторную привязку |
| Q-09 | P2 | В UI нет явного экспорта/резервной копии метаданных | Добавить экспорт/импорт JSON с валидацией и подтверждением перезаписи |
| Q-10 | P2 | Нет пользовательского сценария удаления аккаунта и связанных данных | Добавить удаление аккаунта с повторным подтверждением и каскадным удалением данных |
| Q-11 | P2 | Нет восстановления пароля и подтверждения email | Добавлять только вместе с безопасным почтовым потоком, сроками токенов и ограничением запросов |
| Q-12 | P2 | Создание и выбор плейлиста используют браузерные `prompt()` | Заменить на собственные диалоги с валидацией, доступностью и мобильной адаптацией |

## 3. Ручной функциональный тест

Для каждого пункта ставить: PASS / FAIL / BLOCKED / NOT RUN. При FAIL прикладывать браузер, ОС, шаги, ожидаемое и фактическое поведение, Console и Network.

## 4. Что добавить — дорожная карта

### Сначала обязательно

1. Интеграционные тесты Worker + D1: регистрация, вход, сессия, CSRF, rate limit, CRUD метаданных.
2. Проверка фактического результата Wrangler build и корректности entrypoint.
3. Исправление синхронизации: удаление данных и конфликты между устройствами.
4. Разделение health/liveness и readiness.
5. Измерение PBKDF2 и D1 на Cloudflare, проверка лимитов выбранного тарифа.
6. E2E smoke в браузере: открыть сайт, импортировать тестовый аудиофайл, воспроизвести, зарегистрироваться, синхронизировать.

### После стабилизации

1. Постоянная локальная медиатека через IndexedDB/OPFS — только если пользователь явно согласен с хранением файлов в браузере.
2. Экспорт/импорт библиотеки и резервные копии метаданных.
3. Редактор тегов: название, исполнитель, альбом, обложка.
4. Очередь воспроизведения и управление очередью.
5. Перетаскивание файлов, папок и сортировка.
6. Более удобные диалоги вместо prompt/confirm.
7. Восстановление пароля и подтверждение email.
8. Удаление аккаунта и экспорт пользовательских данных.
9. Сбор обезличенной телеметрии ошибок только с явным согласием; без передачи аудиофайлов.

## 5. Definition of Done для релиза

Релиз Web Edition можно считать готовым только когда:

- [ ] `npm run check` проходит на чистом checkout.
- [ ] Worker build создаёт ожидаемый entrypoint.
- [ ] Локальные D1 migrations применяются с нуля и повторно.
- [ ] Все критические ручные сценарии A–E пройдены.
- [ ] Нет открытых P0/P1 дефектов.
- [ ] Регистрация/вход/выход/CSRF/rate limit проверены интеграционно.
- [ ] Синхронизация проверена минимум в двух независимых браузерах.
- [ ] Проверены Windows + Chrome/Edge и мобильный Safari/Chrome.
- [ ] Production deploy и smoke после deploy успешны.
- [ ] В отчёте указаны реальные версии Node/Wrangler, коммит, результаты CI и ссылки на логи.

## 7. Правила проведения

1. Не проверять сразу на production с настоящими пользовательскими данными — сначала local D1 или preview.
2. Для регистрации и синхронизации использовать тестовые аккаунты и тестовые аудиофайлы.
3. Не помещать пароли, cookie, токены и персональные данные в issue/логи.
4. Любой найденный дефект сначала воспроизвести, затем записать шаги и только после этого исправлять.
5. Не отмечать тест PASS по одному лишь наличию нужной строки в исходном коде.
